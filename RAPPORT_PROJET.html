📱 Rapport de Projet — Application Mobile « Masrouf » (مصروف)

Projet : Développement d'Application Mobile React Native

Auteur : Mini-Projet Étudiant  |  Date : Novembre 2026

Environnement : React Native (Expo SDK 58), TypeScript, SQLite (expo-sqlite), Expo Router

1. Description du Sujet du Projet

« Masrouf » (مصروف) est une application mobile d'assistance budgétaire domestique destinée à aider les ménages à maîtriser leurs dépenses d'épicerie et de consommation quotidienne.

Elle résout les problématiques suivantes :

  • Oubli des tarifs réels payés pour les produits de première nécessité.
  • Absence de comparaison rapide entre les grandes surfaces (Carrefour, Monoprix, Aziza, MG).
  • Dépassement imprévu du budget mensuel fixé.
Fonctionnalités clés développées :
  • Authentification sécurisée avec rôles multiples (Administrateur et Utilisateur standard).
  • Gestion et calcul automatique du budget mensuel en Dinars Tunisiens (TND).
  • Barre de progression dynamique avec alertes événementielles à 80 % et au dépassement.
  • Catalogue de produits avec recherche instantanée par nom ou marque.
  • Fiche détaillée par article avec calcul automatique du meilleur prix historique et de l'enseigne la moins chère.
  • Analyses budgétaires graphiques avec répartition par catégorie et comparaison mois courant / précédent.
  • Support bilingue intégral (Français et Arabe) via des ressources qualifiées.
  • Tableau de bord administrateur avec supervision de tous les comptes et ajustement des budgets.

3. Spécifications des Cas d'Utilisation

UC1 : Se connecter (Authentification)

  • Acteur : Utilisateur ou Administrateur.
  • Scénario nominal : L'utilisateur renseigne email et mot de passe. Si le compte existe dans la table SQLite utilisateurs, il est injecté dans le contexte global AuthContext et redirigé vers l'accueil.
  • Scénario alternatif : En cas d'identifiants incorrects, un message d'erreur rouge s'affiche.

UC2 : Enregistrer un achat

  • Acteur : Utilisateur.
  • Scénario nominal : Clic sur « + Achat » → sélection du produit → sélection du magasin → saisie prix unitaire et quantité. Le système calcule le Total = Prix × Quantité. À la validation, la transaction est insérée dans la table SQLite achats et l'accueil met à jour le solde restant.

UC3 : Créer un produit

  • Acteur : Utilisateur ou Administrateur.
  • Scénario nominal : Clic sur « + Produit » → saisie du nom, de la marque, sélection de l'unité (L, kg, pièce) et de la catégorie (🍞, 🥤, 🧼). Le produit est ajouté dans la table produits.

UC4 : Consulter la fiche produit et son historique

  • Acteur : Utilisateur.
  • Scénario nominal : Clic sur un article → navigation vers /produit/[id]. Le système interroge SQLite et calcule automatiquement le meilleur prix (magasin le moins cher) et le prix moyen.

UC5 : Visualiser les analyses mensuelles

  • Acteur : Utilisateur.
  • Scénario nominal : Onglet « Analyses » → requête SQL avec GROUP BY categorie_id. Affichage de barres graphiques proportionnelles et calcul de l'économie réalisée par rapport au mois précédent.

UC6 : Changer la langue (Ressources qualifiées)

  • Acteur : Utilisateur ou Administrateur.
  • Scénario nominal : Dans « Réglages », clic sur 🇫🇷 ou 🇸🇦 → mise à jour de la préférence dans SQLite et dans le Contexte → l'interface se traduit instantanément.

UC7 : Administrer les comptes (Espace Admin)

  • Acteur : Administrateur uniquement.
  • Scénario nominal : Clic sur le badge « 👑 Admin » → supervision de la liste des membres, de leurs dépenses totales et ajustement direct des budgets.

4. Conception de la Base de Données (Modèle Entité-Association)

Table SQLite Colonnes Principales Rôle & Relations
utilisateurs id (PK), nom, email (UNIQUE), mot_de_passe, role, budget_mensuel, langue Comptes avec distinction de rôle ('admin' ou 'utilisateur').
categories id (PK), nom, icone Catégories de produits avec émoticônes associés (🍞, 🥤, 🧼...).
produits id (PK), nom, marque, unite, categorie_id (FK), created_by (FK) Catalogue des articles relié aux catégories et aux utilisateurs créateurs.
magasins id (PK), nom Enseignes de distribution (Carrefour, Monoprix, Aziza, MG...).
achats id (PK), produit_id (FK), utilisateur_id (FK), magasin_id (FK), prix_unitaire, quantite, prix_total, date_achat, mois Table centrale des transactions. Le champ mois ("2026-11") permet le regroupement mensuel rapide.

6. Questions Fréquentes du Professeur & Réponses

Q1 : Comment fonctionne la navigation dans votre application ?
R : Nous utilisons Expo Router. La navigation est basée sur la structure des dossiers : _layout.tsx crée un Stack Navigator, (tabs) crée le Bottom Tab Bar à 4 onglets, les modales s'ouvrent avec presentation: 'modal', et produit/[id].tsx gère les routes dynamiques en extrayant l'ID avec useLocalSearchParams().
Q2 : Où et comment sont stockées les données ?
R : Les données sont stockées localement sur l'appareil dans un fichier SQLite (masrouf.db) via la bibliothèque officielle expo-sqlite. La méthode initDatabase() dans database.ts est exécutée au démarrage pour créer les 5 tables avec leurs clés étrangères si elles n'existent pas encore.
Q3 : Où se trouvent les ressources avec qualificateurs ?
R : Dans src/i18n/fr.json et src/i18n/ar.json. Le qualificateur est la langue (Français / Arabe). Notre hook useTranslation() charge le dictionnaire qualifié correspondant au profil de l'utilisateur, permettant un basculement instantané des libellés dans l'écran Réglages.
Q4 : Comment montrez-vous la programmation événementielle ?
R : Par exemple dans produits.tsx, l'événement onChangeText sur la barre de recherche filtre la liste des articles instantanément en mémoire. Dans nouvel-achat.tsx, chaque modification du prix ou de la quantité recalcule le total en direct à l'écran.
